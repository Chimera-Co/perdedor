# Upstream Check Triage Report (2026-11-26)

This document records the triage decisions for all 132 previously untriaged upstream techniques across 12 tracked sources in Perdedor. Prior to this triage, these techniques were reported as missing in `CHECK_COVERAGE.md`. With these decisions recorded in the check catalog (`perdedor/catalog/checks/`) and upstream source definitions (`perdedor/catalog/upstreams.json`), all missing entries are fully resolved.

## Triage Categories

- **ALREADY COVERED**: An existing, implemented check tests the exact same underlying mechanism or artifact. The technique identifier has been mapped to that check's `equivalents` field.
- **OUT OF SCOPE BY POLICY**: The technique represents active attack behavior (process injection, shellcode delivery), anti-disassembly/anti-dump obfuscation inherent to the sample binary, or active anti-monitoring actions rather than a passive sandbox environment probe. Recorded with status `not_feasible` or in `upstreams.json` with an explicit policy reason.
- **NOT FEASIBLE UNDER XEN/DRAKVUF**: Low-level machine probes (such as direct MSR reads, AMD SVM instructions on VT-x, or #UD fault storms) that can crash or destabilize the Xen HVM guest or the DRAKVUF VMI hypervisor monitor. Recorded with status `not_feasible` with an explicit Xen rationale.
- **TO IMPLEMENT**: Valid, feasible environment or anti-debug checks that can be safely executed from user mode. Recorded as new catalog entries with status `planned`, defining full metadata and detection logic. These form the implementation backlog.
